# AI 面板界面与交互重设计

日期：2026-09-17。状态：设计方案，尚未实施、尚未验收。

## 1. 目标与现状

目标是建立与 IDE 主题协调、正文优先、操作位置明确的 AI 对话面板。以前的主题补丁、按钮增加和简单富文本处理没有完成这个目标。本方案依据用户提供的当前截图、参考截图以及当前 AgentPanel、AgentTimeline、AgentUITheme 代码制定，不把现有冒烟测试通过视为视觉验收通过。

当前可以从代码确认的问题：

| 问题 | 当前实现 | 设计决定 |
| --- | --- | --- |
| 顶部过密 | 40 高标题栏加 94 高工具栏，三排操作常驻 | 单行会话导航；低频操作放更多菜单 |
| 操作位置不明确 | Copy answer、Open code 位于全局工具栏 | 复制归属具体回复；打开代码归属具体代码块 |
| 重复信息 | 顶部和底部均展示模型 | 模型选择统一放在输入框底部 |
| 正文难读 | 正文字体和颜色继承编辑器设置，代码硬编码 Courier New | 界面、正文、代码三种语义字体；独立正文前景色 |
| 用户消息空洞 | 无论长度都占内容区 75% 宽度 | 按内容收缩，最大宽度 80%，右对齐 |
| 工具条过重 | 整行 Panel 充当按钮，详情高度固定 | 紧凑可聚焦工具行，输入和结果分区；详情有最大高度 |
| 工具状态不一致 | 结果更新会把标题箭头重置为折叠符号 | 状态与展开状态独立，更新结果不改变展开状态 |
| Markdown 不完整 | 表格用三个空格连接单元格，引用用竖线字符替代 | 结构化解析和分块渲染，表格必须有真实单元格布局 |
| 流式布局不稳 | 每次增量重设整段 Edit.Text，再布局全部块 | 保留稳定消息 ID，只更新当前变化块，合并布局刷新 |
| 高度估算不准 | 行数乘统一字号估算富文本高度 | 按实际排版尺寸测量，覆盖标题、换行、DPI |
| 输入区碎片化 | 附件按钮、列表、输入框、发送工具条、状态栏分散 | 单个输入卡片，附件与发送操作归入卡片 |
| 窄面板功能消失 | Clear / Context 按宽度直接隐藏 | 收入溢出菜单，功能仍可访问 |

截图中的问号不能仅凭外观认定为模型输出或编码错误。需要检查原始事件、保存文件和控件显示三个环节，确定首次丢失字符的位置。

## 2. 布局

面板分为三个区域：固定会话导航、独立滚动的消息流、固定输入卡片。以 100% 缩放的逻辑像素定义尺寸，实际尺寸随 DPI 缩放。

```text
┌──────────────────────────────────────────┐
│ ‹ 会话   哈希表的实现           ＋   ⋯    │
├──────────────────────────────────────────┤
│                         帮我检查这个函数 │
│                                          │
│ AI 助手                                  │
│ 这里有两个需要调整的地方……               │
│                                          │
│ › 已读取 main.cpp                     ✓ │
│ › 执行编译检查                        ✓ │
│                                          │
│ 建议的修改                               │
│ ┌ C++ ────────────────── 复制  在编辑器打开┐│
│ │ bool contains(...) { ... }             ││
│ └────────────────────────────────────────┘│
│ 复制回复                                 │
│                              ↓ 新消息    │
│ ┌──────────────────────────────────────┐ │
│ │ main.cpp · 选中 18 行 ×              │ │
│ │ 描述问题，或输入 / 选择操作……        │ │
│ │                                      │ │
│ │ ＋  普通审批⌄  V4 Flash⌄         ↑   │ │
│ └──────────────────────────────────────┘ │
│ 当前项目 · DevCPlusAi                     │
└──────────────────────────────────────────┘
```

- 导航高度 44–48；标题超长省略，悬停显示全称。
- 导航只保留会话返回/历史、新会话、更多。设置、诊断日志、导出、清空显示放入更多菜单。
- 默认会话面板建议宽 420–520；320 宽仍可完成发送、附件、审批、切换会话。280 宽保留兼容布局，以溢出菜单承接次要操作。
- 内容左右留白 16–20；宽面板的正文限制最大阅读宽度约 760，避免无限拉长。
- 空输入卡片约 104–128 高，正文输入随内容增长，最多约 8 行且不超过面板高度 35%；之后输入框内部滚动。
- 顶部和底部之外只有消息流承担主要纵向滚动。回到底部按钮不遮挡正文或覆盖主滚动条。

## 3. 视觉规范

以现有 IDE 的深浅主题为基础，为 AI 面板建立独立语义色，避免直接把编辑器标识符颜色用作全部正文颜色。

| 元素 | 深色方案起点 | 用途 |
| --- | --- | --- |
| 面板背景 | #1E1F22 | 主阅读区 |
| 输入与代码背景 | #25272B | 轻微区分容器 |
| 用户气泡 / 悬停 | #2D3035 | 低对比强调 |
| 边界 | #3A3D43 | 1 像素细边线 |
| 正文 | #E4E7EC | 中文与解释文字 |
| 次级文字 | #A0A7B2 | 时间、模型、辅助说明 |
| 强调 | #5B9CF6 | 焦点、链接和发送 |

以上是设计起点，落地时检查深浅主题与普通文字至少 4.5:1 的对比度；焦点和状态同时使用形状、文字表达，不只依赖颜色。

- 中文正文优先 Microsoft YaHei UI，界面标签使用 Segoe UI 并提供中文回退，代码使用 Consolas。代码字号独立于正文。
- 正文默认 14–15 逻辑像素、约 1.55 行高；辅助文字 12–13；标题 17–20。保留用户字号设置。
- 间距使用 4、8、12、16、24；段落间距 8–12；消息间距 20–24。
- 输入框和用户气泡圆角 8；工具行可无外框或 6 圆角；避免每一段都套大卡片。
- 正常按钮使用扁平图标或文字；仅发送、审批的主要操作需要明显背景。图标有悬停提示、可访问名称和焦点态。
- 中文界面下统一为中文操作文案；命令、路径、模型 ID 保持原样。

## 4. 消息与 Markdown

消息数据至少区分 user、assistant、tool、notice、approval，各自有稳定 ID；展示状态不能作为历史数据来源。保存原始 Markdown、角色、工具关联和必要状态，显示时重新排版。

### 用户消息与回复

- 用户消息使用随内容收缩的右侧气泡；多行自动换行，长路径不会撑宽面板。
- AI 回复左对齐，以正文为主；每轮回复起始展示一次身份，正文与工具调用穿插时保留连续感。
- 回复复制按钮附在该回复尾部，悬停或键盘聚焦时显现；不要让全局复制只指向不明确的“最后一次”。
- 通知使用轻量行，错误使用可展开说明。调试日志只在诊断视图中出现；用户需要处理的失败原因仍要可见。

### Markdown 范围

- 支持 H1–H6、段落、粗体/斜体、行内代码、有序/无序嵌套列表、引用、链接、分隔线、围栏代码块、表格。
- 代码块有语言标识、复制、在编辑器打开；默认保留缩进与长行，横向滚动仅发生在该代码块。超长代码可展开，原始复制内容不受折叠影响。
- 表格使用真实列、表头与单元格；中英文混排保持列对齐；窄面板横向滚动而非空格模拟。
- 引用使用左侧细线与缩进，分隔线使用实际绘制线；列表符号用可靠 Unicode 或绘制，不依赖 ANSI 字节。
- Markdown 解析不改写代码中的星号、下划线、管道、反引号；未闭合语法在流式阶段有稳定降级行为。
- 链接仅在用户点击后打开；来自模型的 HTML/脚本不直接执行。本地打开动作只通过受限宿主接口执行。
- 历史恢复必须与新消息渲染一致；旧数据已损失的字符不伪造恢复。

## 5. 工具与审批

- 工具仍按实际发生位置内联，默认折叠，不能集中移到全局工具抽屉。
- 工具行高约 28–32，左侧折叠箭头、动作摘要，右侧状态和可用的耗时。示例：读取 main.cpp、编译项目；不只显示 Bash [Done]。
- 点击或 Enter/Space 展开，焦点可见；结果到达后保持原展开状态。
- 展开区分别显示输入、输出、错误；支持复制，长输出限制最大高度并内滚动，滚到边缘时自然交给外层消息区。
- 连续的同一批工具可原位分组，但不跨越中间正文，工具条目本身仍可独立展开。
- 普通模式必须在执行前获得决定。审批内容包含工作目录、命令/文件及操作说明；允许一次、拒绝、关闭拒绝的语义明确。
- 审批卡片和现有弹窗共享一个请求 ID 和决定状态，避免双重提交；先保留可靠弹窗流程，再决定是否迁移为内联审批。

## 6. 输入、上下文与会话

- 输入卡片上方显示可删除的上下文标签：文件名、选区行数、图片缩略图；可展开查看实际内容和截断提示。
- 附件操作统一放入“＋”；直接粘贴图片、文件拖入继续支持。每个附件自行移除，不再常驻独立 Remove 按钮。
- 解释、修复、优化、添加注释、分析编译错误放入 / 菜单与空会话快捷项；操作先生成可编辑输入，再由用户发送。
- 明确当前自动附带的编辑器上下文。移除后，本轮发送不得又静默自动附加；“当前文件”和“选区”来源清晰。
- Enter 发送、Shift+Enter 换行，并尊重已有 Ctrl+Enter 配置；中文输入法候选确认不能触发发送。
- 等待/生成中发送按钮变为停止，输入草稿仍可编辑；停止后保留已收到的内容并显示已停止。
- 模型默认 deepseek-v4-flash；模型和审批模式集中放在输入底栏，窄屏进入更多菜单。切换生效范围明确，不能在执行中静默改变权限。
- 会话列表展示标题、更新时间，可搜索和新建；切换时保存草稿、滚动位置和展开状态。
- “新会话”创建新的模型会话；“清空显示”明确不会抹除模型记忆，放入更多菜单避免与新会话混淆。

## 7. 滚动与性能

- 用户位于底部时，新内容随输出跟随；用户滚轮上移或正在选择文字时进入阅读状态，不抢回底部。
- 阅读状态显示“↓ 新消息”；点击后恢复跟随，到底部则隐藏按钮。
- 用可见消息 ID 和块内偏移保持阅读位置，不能只保留旧像素滚动值；宽度变化、字体变化、工具展开均保持阅读锚点。
- 流式更新按短时间窗口合并，初始候选约 30–50ms，通过测量调整；仅重排活动块，完成的消息保持稳定。
- 目标测试量：200 条消息、长代码块、100 次工具事件及连续输出；记录输入响应、布局次数和滚动位置，不仅检查是否抛异常。

## 8. 实现路径与阶段门槛

保留 Delphi/VCL 主程序、Agent 进程、审批协议、文件与会话服务；将 AI 展示层与这些业务服务分开。

第一步做可视原型，覆盖正常对话、代码/表格、工具展开、审批、空会话、错误六种状态，提供 320/480/800 三种宽度和深浅主题。先确认整个布局具备目标观感。

第二步做渲染技术验证：优先评估嵌入式 HTML 展示层承担消息与输入卡片，通过宿主接口传递发送、停止、复制、文件打开、审批动作。运行时选型、Delphi 7/32 位桥接、分发方式、离线启动、输入法和焦点兼容性必须实测；当前方案不宣称这些已经可用。若不能满足部署约束，再采用 VCL 分块渲染，但必须交付等价的表格、排版和可访问交互，不能退回空格拼接。

第三步建立消息模型、结构化 Markdown 和历史迁移，接入流式更新、代码块及表格；去除展示控件兼任数据存储的依赖。

第四步接入工具卡片、会话导航、上下文标签和输入卡片；合并重复工具栏与状态栏。运行中权限语义保持可验证。

第五步完成滚动锚点、DPI、主题、中文输入法、长会话性能与窗口生命周期验证。父窗口异常要取得调用栈或稳定复现才能宣称根因修复，关闭回调保护只能算已覆盖的一条路径。

最后才编译正式直接运行的 devcpp.exe 并打包，记录源码提交与二进制对应关系。

## 9. 验收标准

- 顶部不再常驻三排按钮；正文、工具和输入区域有明确视觉层级。
- 320/480/800 宽及 100%/125%/150%/200% DPI 下不重叠、截断关键操作；窄屏功能通过菜单可达。
- 提供真实程序深浅主题截图，并与原型逐项比较；控件颜色属性测试不能替代实际截图。
- 固定 Markdown 样例覆盖表格、嵌套列表、中文、链接、未闭合围栏、代码中的 Markdown 符号；复制与保存后内容一致。
- 实际滚轮、拖动滚动条、选择文字、工具展开和流式输出组合测试通过；按钮仅在需要时出现。
- 普通审批允许/拒绝/关闭三条路径通过；未决定前没有执行副作用。
- 新建/切换/恢复会话，草稿、角色、Markdown、工具顺序及阅读位置正确；跨项目隔离。
- 回归测试超时必须定位原因并记录；不能因其他测试通过而将整套测试标为通过。
- 对“没有父窗口”的异常完成可复现验证或保留明确未验证说明，不能用推测代替修复证明。
